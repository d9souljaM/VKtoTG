# Мост VK ↔ Telegram

Бот связывает беседу ВКонтакте и группу Telegram: сообщения, фото, файлы, голосовые, ответы и правки
пересылаются в обе стороны. Работает как публичный бот: любой администратор чата может добавить его
и связать свои чаты по одноразовому ключу — так же, как в [MaxTelegramBridgeBot](https://maxtelegrambridge.ru).

Со стороны VK бот — это **сообщество**: его добавляют в беседу, и оно читает и пишет сообщения
через токен сообщества. Пароль и личный токен пользователя VK не нужны.

## Установка (для владельца бота)

Нужен Python 3.12+.

### 1. Telegram-бот

1. В [@BotFather](https://t.me/BotFather) выполните `/newbot` и сохраните токен.
2. `/setprivacy` → выберите бота → **Disable**. Иначе бот в группах видит только команды.

### 2. Сообщество VK

1. Создайте сообщество (или возьмите существующее). Его название и аватар увидят пользователи.
2. «Управление» → «Работа с API» → «Ключи доступа» → «Создать ключ». Отметьте права:
   **управление сообществом, сообщения сообщества, фотографии, документы**.
3. При запуске бот сам включит нужные настройки сообщества (если у ключа есть право «управление»).
   Если в логе есть предупреждение, включите вручную:
   - «Управление» → «Сообщения» → «Сообщения сообщества»: **включены**;
   - «Сообщения» → «Настройки для бота» → «Возможности ботов»: **включены**,
     «Разрешать добавлять сообщество в чаты»: **да**;
   - «Работа с API» → «Long Poll API»: **включён**, версия **5.199**,
     типы событий: «Входящее сообщение», «Редактирование сообщения».

### 3. Запуск

Все команды выполняются **в папке проекта** (там, где лежит `requirements.txt`).

Windows (cmd):

```bat
cd /d "путь\к\папке\проекта"
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
notepad .env
```

Linux/macOS:

```bash
cd /path/to/project
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
nano .env
```

Впишите в `.env` `TG_TOKEN` и `VK_TOKEN`, сохраните файл и запустите:

```bash
python -m vktg
```

В логе появится `Мост запущен: Telegram @… ↔ VK «…»`.

#### Если Telegram доступен только через VPN

Ошибка `Cannot connect to host api.telegram.org:443` значит, что Telegram недоступен напрямую.
Python не использует системный прокси, поэтому адрес прокси VPN-клиента нужно указать в `.env`:

```
TG_PROXY=http://127.0.0.1:12334
```

Адрес и порт посмотрите в настройках VPN-клиента: «локальный прокси», «HTTP/SOCKS-порт» или «mixed port».
В Windows его же видно в «Параметры» → «Сеть и Интернет» → «Прокси-сервер».
Через прокси идёт только Telegram, VK подключается напрямую. Пока бот работает, VPN должен быть включён.

Через Docker:

```bash
docker build -t vktg .
docker run -d --name vktg --restart unless-stopped --env-file .env -v vktg-data:/data vktg
```

### Сервер (Debian/Ubuntu, systemd)

Первая установка: скопируйте на сервер архив с кодом, `.env` и (если есть) `bridge.db`, затем:

```bash
mkdir -p /opt/vktg && tar -xzf /root/vktg-deploy.tar.gz -C /opt/vktg && bash /opt/vktg/deploy/install.sh
```

Скрипт поставит Python и зависимости, отключит `TG_PROXY`, если Telegram доступен напрямую,
и настроит службу `vktg` с автозапуском.

**Обновление кода.** Соберите архив **без** `.env` и `bridge.db`, чтобы не затереть настройки и связки на сервере:

```bash
tar --exclude=__pycache__ -czf vktg-update.tar.gz vktg requirements.txt deploy
```

```bash
scp vktg-update.tar.gz root@АДРЕС_СЕРВЕРА:/root/
```

На сервере:

```bash
tar -xzf /root/vktg-update.tar.gz -C /opt/vktg && bash /opt/vktg/deploy/install.sh && rm /root/vktg-update.tar.gz
```

Сообщения, пришедшие во время перезапуска, не теряются: они ждут в очереди в `bridge.db`.

## Подключение чатов (для пользователей)

1. Добавьте Telegram-бота в группу.
2. Добавьте сообщество в беседу VK: на странице сообщества кнопка «Добавить в чат».
   Назначьте сообщество **администратором беседы** — иначе оно не видит сообщения.
3. В одном из чатов отправьте `/bridge` — бот пришлёт ключ.
4. В другом чате отправьте `/bridge КЛЮЧ`. Готово.

Связывать и отвязывать чаты могут только их администраторы. Ключ одноразовый и действует 15 минут.

## Команды

| Команда | Что делает |
|---|---|
| `/bridge` | Получить ключ для связки |
| `/bridge КЛЮЧ` | Связать этот чат с чатом, где выдан ключ |
| `/bridge prefix on\|off` | Метки `[VK]` / `[TG]` перед именем отправителя |
| `/bridge direction both\|tg>vk\|vk>tg` | Направление пересылки |
| `/unbridge` | Отключить мост |
| `/status` | Состояние моста |
| `/help` | Инструкция |

## Что передаётся

| | VK → Telegram | Telegram → VK |
|---|---|---|
| Текст, упоминания | ✅ упоминания становятся ссылками | ✅ скрытые ссылки раскрываются в `текст (url)` |
| Ответы (reply) | ✅ | ✅ |
| Правки | ✅ | ✅ (VK разрешает править 24 часа) |
| Фото и альбомы | ✅ | ✅ альбом — одним сообщением |
| Файлы | ✅ GIF — анимацией | ✅ |
| Голосовые | ✅ | ✅ |
| Видео | ссылка (VK не отдаёт файл токену сообщества) | ✅ файлом |
| Стикеры | картинкой | текстом `[стикер 😂]` |
| Пересланные сообщения | текстом | пометкой «Переслано от …» |
| Геопозиция, контакт, опрос | — | текстом |
| Удаление | ❌ | ❌ |

## Ограничения

- **Удаления не синхронизируются.** Telegram Bot API не сообщает об удалениях, а VK не присылает их в Long Poll.
- **Файлы из Telegram — до 20 МБ.** Это ограничение Bot API на скачивание.
- **Темы форума.** Сообщения из VK приходят в общую тему группы Telegram.
- **Очередь доставки хранится в базе.** Сообщения переживают перезапуск бота. При временных сбоях
  сети или API бот повторяет отправку с нарастающей паузой (до 10 минут) в течение суток.
  Ошибки, которые повтором не исправить (например, бота удалили из чата), не держат очередь:
  такое сообщение пропускается с записью в лог. В VK повтор не создаёт дублей. В Telegram при
  сбое посреди сообщения из нескольких частей (текст + альбом + файлы) уже отправленные части
  могут прийти повторно.
- Одна беседа VK связывается только с одной группой Telegram.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TG_TOKEN` | — | Токен Telegram-бота (обязательно) |
| `VK_TOKEN` | — | Ключ доступа сообщества VK (обязательно) |
| `TG_PROXY` | — | Прокси только для Telegram: `http://…` или `socks5://…` |
| `VK_GROUP_ID` | из токена | ID сообщества |
| `VK_AUTO_SETUP` | `1` | Включать нужные настройки сообщества при запуске |
| `DB_PATH` | `bridge.db` | Путь к базе SQLite |
| `LOG_LEVEL` | `INFO` | Уровень логирования |
| `MESSAGE_FORMAT` | `inline` | `inline` — «Имя: текст», `newline` — текст с новой строки |
| `TG_DOWNLOAD_LIMIT_MB` | `20` | Предел файла Telegram → VK |
| `TG_UPLOAD_LIMIT_MB` | `50` | Предел файла VK → Telegram |
| `MAPPING_TTL_DAYS` | `30` | Сколько дней помнить пары сообщений для ответов и правок |

## Разработка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Структура пакета `vktg/`:

| Файл | Назначение |
|---|---|
| `__main__.py` | Запуск: Telegram polling + VK Long Poll |
| `tg_handlers.py` | Команды и сообщения Telegram |
| `vk_handlers.py` | События и команды VK |
| `to_vk.py` / `to_tg.py` | Пересылка в каждую сторону |
| `linking.py` | Привязка чатов по ключу |
| `vk_api.py` | Клиент VK API: методы, загрузка файлов, Long Poll |
| `db.py` | SQLite: связки, ключи, пары сообщений |
| `queues.py` | Очередь доставки в SQLite: порядок по чатам, повторы, переживает перезапуск |
| `deploy/install.sh` | Установка и обновление на сервере (systemd) |
